2. PHASE-BY-PHASE ACHIEVEMENTS
================================================================================

PHASE 1 - FORENSIC AUDIT (nothing changed, everything measured)
  - WAV artifact forensics on captured live outputs
    (bob_received_translated_audio.wav, live_translated_output.wav) found:
    hard zero-runs of 35ms and 113ms (dropouts), dead 250ms windows, and RMS
    at -23.8 / -22.4 dBFS (about 6dB under healthy TTS speech).
  - Algorithm simulation (Python port of the exact Rust resampler) PROVED the
    phase-carry defect before any code was touched: 8,004 outputs where 8,000
    belong, with a discontinuity at every chunk boundary (duplicated sample
    = click; 3-sample backtrack = micro-stutter; net time-expansion =
    hours-long drift).
  - Docs-conformance audit against ollalink.com docs: verified sound-stream
    URL/schema, session.configure shape, 48kHz-stream / 24kHz-WAV lane
    handling, 429/502 semantics, real-time pacing requirement, and the
    documented silent-IP-block failure mode.
  - 12 deep defects identified (D1-D12), each with root cause, mechanism, and
    fix size.
  - Security finding (STILL OPEN): real sk_ dashboard key exposed in
    CHECKPOINT.md (committed), dist-package/server/.env, and the shipped zip.

PHASE 2 - GROUP 1: CORE AUDIO MATH & PRIVACY (commit 1d5185c)
  - D1 (CRITICAL, proven): Resampler phase-carry origin math fixed:
    phase = pos - (total_in - history_kept) in next-chunk coordinates; removed
    the wrong-modulus negative wrap. Boundary clicks, micro-stutters, and
    time-expansion drift eliminated BY CONSTRUCTION. TDD: RED first (2 failing
    tests reproducing 8,004/8,000 and +10-sample drift), then GREEN. Also
    corrected a pre-existing test that had encoded the buggy counts
    (737/186 -> correct 735/184, total 1010).
  - D8 (privacy): Mic hot-swap now passes the live mic_muted arc - a muted
    user who swaps microphones stays muted (was: new stream always unmuted).
  - D11: Server audio routing falls back to the peer's target language in 1:1
    rooms when upstream omits the language field (was: silently dropped ALL
    audio), with a warning log.

PHASE 3 - GROUP 2: TRANSPORT & PACING STABILITY (commit 0f4d666)
  - D2: Token-bucket uplink pacing (CATCHUP_FACTOR=2) - after any stall,
    backlog drains at most 2x real time, so a stall can never burst into
    Ollalink's "overloaded" (4029) socket close.
  - D7: Outbound WS queue bounded at 4 frames (~2s) with drop-stale policy -
    a stalled relay can no longer bank minutes of mic audio and mega-burst on
    reconnect; control frames still use lossless blocking send.
  - D4: Hard 5s timeouts on connect_async and the session-mint HTTP client -
    the docs' documented "hangs with no response" failure mode can no longer
    wedge the client silently.
  - D3: Reconnect completion is now bound to a verified {type:"joined"} reply -
    a socket-open-but-rejected-join (expired token) can no longer leave a
    zombie call that streams the mic into a room it isn't in.

PHASE 4 - GROUP 3: PLAYBACK QUALITY & JITTER TUNING (commit 08921e6)
  - D6: Jitter buffer 60ms -> 160ms - sized for real WAN jitter; kills the
    motorboat stutter the WAV forensics showed.
  - D5: Playback ring cap 4s -> 12s - long batch-WAV sentences are no longer
    front-truncated (a 6s utterance used to lose its first 2 seconds).
  - D9: Relay pre-ready audio buffer 1.5s -> 3.0s (6 chunks) - words spoken
    during cold GPU-lane / 502-retry windows are no longer eaten.
  - D10: Sentence-tail flush on 150ms ring idleness (replaces the wall-clock
    gate) - the last word of every phrase leaves immediately; tail latency
    drops from up to 1.5s to ~150ms + endpointing.
  - D12: +3dB makeup gain after the tanh soft-knee on BOTH uplink send paths,
    plus dynamic downlink peak normalization toward -1 dBFS (per-utterance
    running peak, 4x gain cap, reset on utterance end) - directly addresses
    the measured -23dBFS quiet output.

PHASE 5 - HARDENING THE FIXES THEMSELVES (commit b2347c3)
  Self-review after implementation surfaced two races introduced by the new
  fixes; both fixed:
  - N1: The backlogged pacing branch slept a full chunk-time (500ms) - could
    turn 500ms chunks into ~1.5s send cadence (+1s latency). Now sleeps only
    the credit deficit.
  - N3: The rejoin verifier registered its waiter AFTER sending the join
    frame - a fast "joined" reply resolved an empty registry and the 5s wait
    falsely timed out healthy reconnects. Waiter now registered before
    open_socket; also cancelled on the error path.

PHASE 6 - DE-OVERENGINEERING (commits cbf2f7d, 29ff3e5, d36fc62)
  -2,474 lines removed, release build now warning-free:
  - Dead 258-line sound_stream.rs upstream-protocol adapter (the app never
    talks to Ollalink - the relay does), dead ClientFrame enum,
    stored-never-read struct fields (relay, ring_prod_parked), six
    never-called methods, unused frame_ms config.
  - DISCOVERED + DEFUSED a live footgun: Vite resolves .js before .ts - the
    tracked, compiled .js twins in ui/src silently shadowed .ts edits.
    Verified twins were currently in sync (byte-identical hash check), then
    deleted, untracked, and gitignored.
  - Test-only jitter API gated behind #[cfg(test)].
  - Chesterton's-fence discipline: kept /api/langs, /api/probe-language,
    the _replacedByNewConnection guard, and all regression-guard queues
    despite "looks complex" - each is a tested regression guard.

PHASE 7 - ARTIFACT REBUILD & VERIFICATION (commit b2347c3)
  - Full tauri build (release + NSIS) with the fixed code.
  - Updated: root ollalink-translate.exe (14,416,896 B),
